# Mighty Mouse v0.4.0

Mighty Mouse v0.4.0 introduces canonical Multi-Agent Swarm execution with isolated verification and the MCP v6 `swarm_execute` interface.

## Release changes

- **Canonical Multi-Agent Swarm Orchestration**:
  - Decomposed execution into specialized subagents: SwarmPlanner, SwarmCoder, and SwarmReviewer.
  - Multi-turn refinement loops with dynamic temperature annealing and reviewer feedback.
  - Non-mutating candidate generation ensuring zero intermediate workspace side effects.

- **Winner-Only Application Boundary**:
  - Deterministic response application strictly gated on reviewer `PASS`.
  - Single-winner application policy preventing partial, unvalidated, or loser candidate writes.
  - Strict delete authorization policy restricting file removals to explicitly authorized targets.

- **Canonical Isolated Verification**:
  - Out-of-place candidate verification executed against fresh disposable copies of isolated workspaces.
  - Strict pre-execution workspace non-overlap validation rejecting exact, nested, or symlinked paths.
  - Public `task_config` verification support including custom test scripts, expected files, and checklist adherence.

- **Host Provenance & Ollama Binding**:
  - Authoritative `HostAdapter.solve_swarm` execution path binding Ollama model digests and runtime metadata.
  - Fail-closed execution profile validation preventing unvalidated configuration execution.

- **MCP v6 & Canonical Swarm Execution**:
  - Bumped `MCP_TOOL_CONTRACT_VERSION` from 5 to 6 (15 total tools).
  - Added `swarm_execute` MCP tool routing directly to `HostAdapter.solve_swarm`.
  - Bounded public MCP result projection suppressing sensitive reviewer feedback, command logs, and raw model output.
  - Whitelisted host provenance metadata exposing strictly authorized execution attributes.

## Upgrade & Compatibility Notes

- **Adapter Re-onboarding**: Workspaces configured under MCP tool contract v5 fail closed as stale and require running `setup_workspace(..., replace=True)`.
- **Profile-Bound Pins**: Previously pinned scaling or policy configurations under v5 execution profiles do not match v6 execution profiles and must be re-pinned under the new profile.
- **Legacy CLI Swarm Behavior**: Standalone invocations via `--mode swarm` remain direct, adapter-free, and non-mutating.
- **Agent Execute Compatibility**: `agent_execute` remains fully supported and operational under re-onboarded v6 execution profiles.
